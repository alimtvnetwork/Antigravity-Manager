# Fix document for Claude Code "Field required" error

## 1. Problem background
When using Claude Code CLI and proxying through Antigravity-Manager, the following error often occurs:
`messages.X.content.0.text.text: Field required`

**root cause**:
When Claude Code makes a tool call (Tool Use), the message block sent or received may contain an empty `text` field (such as `{"text": ""}` or `{"text": " "}`).
- **Google Gemini API**: Including empty text blocks in requested `parts` is strictly prohibited.
- **Anthropic Protocol Conversion**: During the conversion process, failure to `trim()` and validate the empty string will cause the upstream API to reject the request.

## 2. Targeted modifications to the plan

This repair mainly involves two core files in the `src-tauri/src/proxy/mappers/claude/` directory:

### A. Request-side filtering (src-tauri/src/proxy/mappers/claude/request.rs)

**Modification Notes**: Strict filtering of all `ContentBlock::Text` and downgraded thinking blocks (Thinking) when converting Claude messages to Google format.

* **Modification point 1 (`build_contents` function)**:
    * **Status quo**: Only equality to the `(no content)` placeholder is checked.
    * **FIX**: Introduced `!text.trim().is_empty()` to ensure that all text blocks sent to Google contain actual content.
* **Modification point 2 (Think block downgrade)**:
    * **Status quo**: When thought mode is disabled or the blocks are out of order, thought blocks are converted to `text` blocks.
    * **Fix**: Ensure that whitespace-only text is excluded during downgrade and `trim()` the content.

### B. Responder optimization (src-tauri/src/proxy/mappers/claude/streaming.rs)

**Modification description**: Optimize the streaming response conversion logic to prevent sending empty blocks that induce state machine exceptions to the client.

* **Modification point 1 (`emit_finish` function)**:
    * **Status quo**: When processing web search (Grounding) results, a `text` block is initialized.
    * **Fix**: Allow sending this content chunk fragment only if the search digest `grounding_text.trim()` is indeed non-empty.
* **Modification point 2 (`process_text` processor)**:
    * **Fix**: Enhanced the logic robustness in `trailing_signature` (signature staging) scenario to ensure that meaningless "ghost" text blocks are not generated.
