# Root Cause Analysis (RCA): Inbound Email HTML Responses, Origin Node Identity & IDE Smart Account Rotation

**Issue ID:** RCA-2026-09-24-001  
**Severity:** CRITICAL / HIGH  
**Scope:** Email Inbound/Outbound Engine (`email_inbound.rs`, `email_sender.rs`, `notification_hub.rs`), Auto Switcher (`auto_switcher.rs`), Multi-Instance Management (`instance.rs`)

---

## Part 1: Symptoms and Context

1. **Escaped HTML Tags Rendered Literally in Email Clients**:
   - In Gmail and Outlook, inbound response receipts and notification emails rendered raw HTML tags (e.g. `<div style="...">`, `<table>`, `<tr>`) verbatim in the message body instead of visual styled UI cards.
   - Users received ugly, unreadable text dumps containing raw styling directives.

2. **Missing VM Node Identity and IP in Email Subjects**:
   - When managing multi-node clusters across multiple virtual machines (e.g., VM1, VM2, VM3), outbound receipts and alerts had generic subjects like `[AGM Result] SUCCESS: status` or `Re: [AGM Help]`.
   - Operators could not immediately tell which VM or local IP address dispatched the message without digging through message headers.

3. **Remote Account Switching Ineffective on Active Antigravity IDE**:
   - When users sent remote email commands to switch accounts (e.g., `VM3 | switch | user@example.com` or `agm ff`), the email receipt reported `SUCCESS`, but the running Antigravity IDE continued executing with the previous account.
   - The switch was cosmetic only: it updated SQLite index metadata but failed to inject the OAuth token into the IDE sandbox database (`state.vscdb`), update the system keyring, bind the instance profile, or restart the IDE process.

4. **Rigid Pipe Separator Syntax in Email Subject/Body**:
   - Command parsing strictly expected specific spacing around pipes, failing or misinterpreting commands when users wrote zero spaces (`VM3|1|help`), single spaces (`VM3 | 1 | help`), or multiple spaces (`VM3   |   1   |   help`).

## Part 2: Root Cause Analysis (4-Part RCA)

### 2.1 RFC 2046 MIME Content-Type Hardcoding
In `src-tauri/src/modules/email_sender.rs` (`build_mime_message`), the outbound email MIME generator unconditionally emitted:
```text
Content-Type: text/plain; charset=UTF-8
```
Even when callers provided rich HTML strings generated by `render_html_receipt` or notification templates, mail clients strictly adhered to RFC 5322/2046 and displayed the payload as plain text, exposing raw HTML tags.

### 2.2 Incomplete IDE Credential Injection Sequence in Remote Inbound Handler
In `src-tauri/src/modules/email_inbound.rs` (`execute_inbound_action`), the handler for `InboundAction::AccountSwitch` executed:
```rust
crate::modules::account::set_current_account_id(&target_acc.id);
let _ = crate::modules::account::apply_device_profile(&target_acc.id);
```
Crucially, it missed the full Antigravity credential injection sequence implemented in `instance::switch_account_to_instance`:
1. Ensuring a fresh OAuth token via `oauth::ensure_fresh_token`.
2. Encrypting and writing the access token into the IDE instance sandbox database (`%APPDATA%/Antigravity/User/globalStorage/state.vscdb`).
3. Updating the OS system keyring/credential manager.
4. Binding the account ID to the instance registry (`registry.instances[i].bound_account_id`).
5. Terminating and relaunching the instance process to load the fresh session credentials.
6. Failure to invoke `auto_switcher::select_next_best_profile` when no specific account was provided.

### 2.3 Absence of Origin Node Aliasing in Subject Formatters
In `format_reply_subject` and notification templates (`render_quota_drop_email`, `render_workspace_switch_email`, etc.), outbound subjects were constructed without querying local node metadata (`local_machine_name` and `local_machine_ip`), preventing operators from distinguishing nodes in cluster environments.

### 2.4 Pipe Tokenization Fragility
String parsing in `parse_single_command_string` split inputs on `|` but did not cleanly isolate instance specifiers (`1`, `#1`, `ins-1`) from trailing command payloads and arguments when varying whitespace was present.

## Part 3: Architecture & Engineering Remedy

### 3.1 RFC 2046 Multipart/Alternative MIME Engine
Refactored `email_sender.rs`:
- Implemented `is_html_content(body: &str) -> bool` to detect HTML markup tags (`<html`, `<div`, `<table`, `<!doctype`).
- Implemented `strip_html_tags(html: &str) -> String` to generate clean, legible plain-text fallback representations.
- Updated `build_mime_message` to construct standard RFC 2046 `multipart/alternative` boundaries containing:
  - Part 1: `Content-Type: text/plain; charset=UTF-8`
  - Part 2: `Content-Type: text/html; charset=UTF-8`

### 3.2 Full Smart Rotator & IDE Credential Injection Integration
Refactored `instance.rs`, `auto_switcher.rs`, and `email_inbound.rs`:
- Implemented `instance::resolve_instance_id` to map numeric indices (`1`), formatted identifiers (`ins-1`, `#1`), profile names, and keywords (`default`, `active`) to actual instance GUIDs.
- Created `auto_switcher::trigger_manual_rotation_for_instance(target_instance_id: Option<&str>)` enabling candidate scoring and rotation per instance.
- Wired `InboundAction::AccountSwitch`:
  - If query is empty or `smart`/`ff`/`rotate`/`next`: delegates to Smart Rotator (`trigger_manual_rotation_for_instance`).
  - If query specifies an account: scores and finds matching account, executes `instance::switch_account_to_instance`, performing complete OAuth refresh, `state.vscdb` injection, keyring update, and process relaunch.
- Wired `InboundAction::FastForward` and `InboundAction::AccountRotate` to `trigger_manual_rotation_for_instance`.

### 3.3 Prominent Node Identity in Subject Headers
- Prepend `[<NODE_ALIAS> | <LOCAL_IP>]` (e.g. `[VM3 | 192.168.1.12]`) to all outbound email subjects across ACK receipts, result cards, and alert dispatches.
- Updated `format_reply_subject` to strip duplicate brackets when replying in threaded conversations while preserving node attribution.

### 3.4 Flexible Pipe and Argument Parser
- Enhanced `parse_single_command_string` with `.split('|').map(|s| s.trim()).filter(|s| !s.is_empty())`.
- Accurately parses commands with 0 spaces (`VM3|1|help`), 1 space (`VM3 | 1 | help`), and multiple spaces (`VM3   |   1   |   help`).
